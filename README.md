This is a tool which can be run inside a CICD pipeline, after a CheckmarxOne ast-cli scan step, to trigger AI Remediation on a set number of vulnerabilities (default=1). 
It prioritizes by highest-risk first, and sorts SAST, SCA, and IAC results by the resultHash/alternateId provided by the platform.
It requires the cx_result.json report generated by cx.exe when using the --report-type json flag.

# Usage
An example of using this in a CICD pipeline:
1. Pipeline receives source code
2. Pipeline triggers a CheckmarxOne scan with thresholds / build break + json report
3. The scan fails due to new issues
4. This tool is invoked with CheckmarxOne authentication credentials, a github token with sufficient permissions to write files+create a PR in a new branch on the code's source repository
5. This tool triggers AI Triage and/or AI Remediation on the specified number of findings, submitting them to CheckmarxOne in batches (at most 5 per request)
6. This tool applies each code-remediation generated by CheckmarxOne in memory to the original files (the local files are not modified)
7. Using the provided token, this tool creates a new branch on the code's source repository for each remediation
8. Using the provided token, this tool raises a new pull request for each remediation against the specified branch (eg: main)

At this point a developer can review the PRs, merge to main, and trigger the pipeline again.

## Multiple remediations
Every remediation is applied in memory against the original, unmodified source files. The local files are never changed by this tool, so nothing AI-generated persists in the workspace after it exits - remediations are delivered only as pull requests.
Each pull request therefore contains only its own fix, and two remediations that touch the same file (for example pom.xml) each apply cleanly.
If their changes overlap, the second PR to be merged will show an ordinary merge conflict on GitHub.

A remediation is all-or-nothing: if any of its changes cannot be applied, no PR is created for it.

A GitHub token is required when using -remediate; the tool exits before submitting anything to CheckmarxOne if none is available.

# Parameters
## Auth
```
  -apikey string
        CheckmarxOne API Key (if not using client id/secret)
  -client string
        CheckmarxOne Client ID (if not using API Key)
  -cx1 string
        Optional: CheckmarxOne platform URL, if not defined in the test config.yaml
  -githubToken string
        GitHub token used to publish a pull request with the remediation changes (falls back to the GITHUB_TOKEN env var); required when using -remediate
  -iam string
        Optional: CheckmarxOne IAM URL, if not defined in the test config.yaml
  -secret string
        CheckmarxOne Client Secret (if not using API Key)
  -tenant string
        Optional: CheckmarxOne tenant, if not defined in the test config.yaml
  -token string
        Optional: A valid access_token. If this value is provided, others will be ignored - the client will lose access when the token expires
```
## Process       
```
  -baseBranch string
        Branch to open the pull request against; defaults to the repository's default branch
  -dir string
        Path to the root of the source code that was scanned, used as the base that remediation diffs are applied to in memory (never modified) (default ".")
  -engine string
        Focus only on this engine (sast,sca,iac) - if blank then sort by severity + resultId
  -input string
        Path to JSON format report as generated by ast-cli --report-type json (default "cx_result.json")
  -triage int
        Number of results to triage, sorted by highest-priority and resultId (default 0)
  -triageBatch int
        Number of results submitted to AI Triage together in one request (1-5) (default 5)
  -prBranch string
        Name of the new branch to create for the pull request; auto-generated if omitted. When remediating more than one result, each pull request's branch is this name plus a result-specific suffix
  -remediate int
        Number of results to remediate, sorted by highest-priority and resultId (default 1)
  -remediationBatch int
        Number of results submitted to AI Remediation together in one request (1-5) (default 5)
  -repo string
        Target GitHub repository (owner/repo, https URL, or SSH URL) for the pull request; derived from the Checkmarx One project's repoUrl if omitted
  -scanId string
        Scan ID for the processed scan report
```

## Misc  
```
  -log string
        Log level: TRACE, DEBUG, INFO, WARNING, ERROR, FATAL (default "INFO")
  -useragent string
        Optional: A custom user-agent string for all requests to Cx1 (default "Cx1ClientGo")
```

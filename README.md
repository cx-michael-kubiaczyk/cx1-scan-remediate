This is a Proof-of-Concept tool which can be run inside a CICD pipeline, after a CheckmarxOne ast-cli scan step, to trigger AI Remediation on a set number of vulnerabilities (default=1). 
It prioritizes by highest-risk first, and sorts SAST, SCA, and IAC results by the resultHash/alternateId provided by the platform.
It requires the cx_result.json report generated by cx.exe when using the --report-type json flag.

# Usage
An example of using this in a CICD pipeline:
1. Pipeline receives source code
2. Pipeline triggers a CheckmarxOne scan with thresholds / build break + json report
3. The scan fails due to new issues
4. This tool is invoked with CheckmarxOne authentication credentials, a github token with sufficient permissions to write files+create a PR in a new branch on the code's source repository
5. This tool triggers AI Triage and/or AI Remediation on the specified number of findings, submitting them to CheckmarxOne in batches (at most 5 per request)
   - AI Triage is only run on findings in the To_Verify state
   - AI Remediation is only run on findings in the Confirmed or Urgent state (including those just triaged to one of these states)
6. This tool applies each code-remediation generated by CheckmarxOne in memory to the original files (the local files are not modified)
7. Using the provided token, this tool creates a new branch on the code's source repository for each remediation
8. Using the provided token, this tool raises a new pull request for each remediation against the specified branch (eg: main)

At this point a developer can review the PRs, merge to main, and trigger the pipeline again.

## Multiple remediations
Every remediation is applied in memory against the original, unmodified source files. The local files are never changed by this tool, so nothing AI-generated persists in the workspace after it exits - remediations are delivered only as pull requests.
Each pull request therefore contains only its own fix, and two remediations that touch the same file (for example pom.xml) each apply cleanly.
If their changes overlap, the second PR to be merged will show an ordinary merge conflict on GitHub.

A remediation is all-or-nothing: if any of its changes cannot be applied, no PR is created for it.

## Notes
- By default only one finding is triaged (`-triage 1`) and is remediated (`-remediate 1`), to avoid burning AI tokens. Both are configurable.
- AI Triage / AI Remediation requests are sent in batches of at most 5 findings (`-triageBatch` / `-remediationBatch`). `-remediate` and `-triage` themselves are not capped, so a larger number is simply split into several batches. The batch limit of 5 is hard-coded as it is the size the AI backends are known to handle.
- Triage runs before remediation, and its outcome is taken into account: a To_Verify finding that triage moves to Confirmed or Urgent can be remediated in the same run, while any other finding left in To_Verify (or Not_Exploitable) is not remediated.

A GitHub token is required when using -remediate; the tool exits before submitting anything to CheckmarxOne if none is available.

# Pipeline Script
For easy testing, the scan_and_check.sh script is available on this repo and could be triggered directly from a pipeline, for example:
```
curl -L https://raw.githubusercontent.com/cx-michael-kubiaczyk/cx1-scan-remediate/refs/heads/main/scan_and_check.sh -o /tmp/scan_and_check.sh && \
  chmod +x /tmp/scan_and_check.sh && \
  /tmp/scan_and_check.sh
```

This script will do the following:
1. Download & unpack the CheckmarxOne ast-cli (https://github.com/Checkmarx/ast-cli/releases/latest/download/ast-cli_linux_x64.tar.gz)
2. Run a scan with all engines against the pipeline's source code using CheckmarxOne, failing if there is any Critical or High result (thresholds are set per engine)
3. If the scan fails, it will download the cx1scanremediate binary from this repository's releases
4. Run the cx1scanremediate tool to trigger CheckmarxOne AI-Triage on up to 5 Critical/High SAST and SCA findings in the To_Verify state, then AI-Remediation on the most-severe Confirmed or Urgent finding (if any)
5. Once a code-remediation is available, apply the code fix and raise a pull request against the original repository

The script takes variables from the pipeline for each step (CheckmarxOne URLs & credentials, Github URLs & PAT):
- GH_PR_PAT: token allowing permission to write & raise PRs in the target repository
- GH_REPO_URL: location of the target repository
- BRANCH: PRs raised by this tool will target this branch + scans in CheckmarxOne will be listed under this branch
- PROJECT_NAME: scans in CheckmarxOne will be created under this project
- CX1_URL: URL for the CheckmarxOne instance eg: https://deu.ast.checkmarx.net
- IAM_URL: Authentication URL for the CheckmarxOne instance eg: https://deu.iam.checkmarx.net
- CX1_TENANT: Tenant in the CheckmarxOne instance
- CX1_CLIENT: OIDC Client ID to use for connecting to CheckmarxOne
- CX1_SECRET: OIDC Client Secret to use for connecting to CheckmarxOne
- CX1SR_PROXY: Optional HTTP proxy to use by the cx1-scan-remediate tool
- CX1SR_LOGLEVEL: Optional Log level to use for output by the cx1-scan-remediate tool (default: info)
- CX1SR_DEBUG: Optional Debugging flag to retain diffs generated by CheckmarxOne AI-Remediation - diffs are stored in temporary files (eg: in /tmp/) and are deleted automatically if this field is empty

This tool is a Proof-of-Concept and has a number of limitations outlined below.

# Parameters
## Auth
```
  -apikey string
        CheckmarxOne API Key (if not using client id/secret)
  -client string
        CheckmarxOne Client ID (if not using API Key)
  -cx1 string
        Optional: CheckmarxOne platform URL, if not defined in the test config.yaml
  -githubToken string
        GitHub token used to publish a pull request with the remediation changes (falls back to the GITHUB_TOKEN env var); required when using -remediate
  -iam string
        Optional: CheckmarxOne IAM URL, if not defined in the test config.yaml
  -secret string
        CheckmarxOne Client Secret (if not using API Key)
  -tenant string
        Optional: CheckmarxOne tenant, if not defined in the test config.yaml
  -token string
        Optional: A valid access_token. If this value is provided, others will be ignored - the client will lose access when the token expires
```
## Process       
```
  -baseBranch string
        Branch to open the pull request against; defaults to the repository's default branch
  -dir string
        Path to the root of the source code that was scanned, used as the base that remediation diffs are applied to in memory (never modified) (default ".")
  -engine string
        Focus only on these engines - comma separated list from: sast,sca (default "sast,sca")
  -input string
        Path to JSON format report as generated by ast-cli --report-type json (default "cx_result.json")
  -severity string
        Focus only on results of these severities - comma separated list from: CRITICAL,HIGH,MEDIUM,LOW,INFO (default "CRITICAL,HIGH")
  -triage int
        Number of results to triage, sorted by highest-priority and resultId (default 0)
  -triageBatch int
        Number of results submitted to AI Triage together in one request (1-5) (default 5)
  -prBranch string
        Name of the new branch to create for the pull request; auto-generated if omitted. When remediating more than one result, each pull request's branch is this name plus a result-specific suffix
  -remediate int
        Number of results to remediate, sorted by highest-priority and resultId (default 1)
  -remediationBatch int
        Number of results submitted to AI Remediation together in one request (1-5) (default 5)
  -repo string
        Target GitHub repository (owner/repo, https URL, or SSH URL) for the pull request; derived from the Checkmarx One project's repoUrl if omitted
  -scanId string
        Scan ID for the processed scan report
```

## Misc  
```
  -log string
        Log level: TRACE, DEBUG, INFO, WARNING, ERROR, FATAL (default "INFO")
  -useragent string
        Optional: A custom user-agent string for all requests to Cx1 (default "Cx1ClientGo")
```

# Limitations
This tool has various limitations as it is intended for a Proof-of-Concept demonstration.
1. Only SAST and SCA findings are processed; IaC is not currently supported by AI Triage/Remediation.
2. If two remediations change overlapping lines of the same file, the second PR to be merged will have a merge conflict.
